## 密码与会话

在 **Vercel 管理项目**设置 `ADMIN_ENTRY_PASSWORD`，至少 12 个字符、UTF-8 不超过 256 字节，建议 16 位以上随机密码；不加 `PUBLIC_` / `VITE_` 前缀。保存后重新部署管理项目；Preview / Development 使用隔离密码。没有配置、过短、全空格或超长时入口关闭，没有默认生产密码。

`POST /api/auth/entry` 只接受管理同源的有限大小 JSON。服务端恒定时间校验密码后，在事务内创建随机管理员会话并撤销浏览器的旧会话；客户端不能指定用户身份或固定登录令牌。数据库只保存会话令牌与 CSRF 的摘要、管理员资料和到期时间，不保存密码。

一次验证自动设置 `__Host-admin-session` 和 `__Host-admin-entry` 两种 Cookie，均为 Secure、HttpOnly、SameSite=Lax、Path=/，有效期 12 小时，不需要用户做第二次操作。入口凭证带随机 nonce、到期时间和 HMAC，签名密钥由密码及站点/环境/域名经 scrypt 派生。管理接口同时检查两种凭证；写请求继续校验管理 Origin 与 CSRF。退出登录撤销数据库会话并清除凭证；更换密码并重新部署使旧入口凭证失效。密码不进入 Git、静态资源或浏览器存储。

旧 GitHub 会话不再有效；`/api/auth/github` 和 `/api/auth/callback` 已移除，返回 404。登录不调用外部认证提供者，不再读取 `ADMIN_GITHUB_USER_ID`、`GITHUB_OAUTH_CLIENT_ID`、`GITHUB_OAUTH_CLIENT_SECRET`。GitHub App 的三个变量仍用于仓库导入、核查与发布，独立于密码登录。数据库迁移保持兼容，已有 `oauth_states` 表只保留旧数据清理用途，不再创建登录 state。

登录限流使用 PostgreSQL 持久计数和事务锁：每个 IP 每 10 分钟最多 5 次尝试，站点窗口最多 100 次；数据库只保存 IP 的 HMAC 摘要。生产只接受 Vercel 的受信转发地址。入口状态查询无需数据库；没有认证会话的管理请求在读取私有数据前被拒绝。第三方签名回调和 Cron 继续使用各自认证。
