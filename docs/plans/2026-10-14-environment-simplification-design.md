# 环境变量精简

用户要求仅手填必需变量，能由博客或平台确定的配置自动完成。

基础后台只需要密码和隔离 PostgreSQL 连接。仓库操作保留 GitHub App ID/私钥，安装 ID 由目标仓库接口查询；发布保留 Vercel token，项目 ID 优先读取平台变量，团队沿用 token 作用域。媒体保留私有/公开 Blob 凭据，互动保留 Turnstile 公钥/私钥。

运行环境来自 Vercel，预览 origin 使用平台部署 URL。生产 origin、邮件发件人和默认图片导入主机从已发布博客设置获取；评论接口默认跟随评论组件配置。

用户于 2026-10-14 明确批准“迁移到后台并默认关闭”：将生产发布、邮件和维护三个启用开关迁移到后台“服务设置”。三项默认关闭，只有通过后台密码和有效数据库会话认证的管理员可保存；写请求继续核验同源 Origin、CSRF 和修订号。Preview/Development 永远不能启用生产能力。服务凭据依然保留在 Vercel Secret，不能通过设置接口读取或保存。启用开关不自动创建发布/恢复任务，仍须点击相应操作。

实现使用现有 entities 表中的私有 service_settings 记录，无需增加数据库迁移。首次及后续保存均使用原子修订号检查；恢复旧备份时保留当前服务设置。开关不缓存，任务执行前重新读取；已经完成或正在执行的外部操作不会被撤回。

三个 ENABLE_PRODUCTION_* 变量停止读取，权限以后台设置和真实平台环境为准。其余高级配置覆盖项保留兼容。不自动猜测凭据、放开跨源请求、共享生产/预览数据库，或把私有配置写入公开站点设置。

Vercel 仅删除已核实的空占位项。邮件、定时维护、恢复演练和开发环境未使用时无需预建空变量；其第三方凭据仍在启用时按需配置。远程修改前后检查项目 ID 和变量元数据，不输出秘密。

验证：新增自动配置行为测试、生产/预览权限回归、GitHub 安装查询和错误响应测试，运行后台测试、两端类型检查、Astro 诊断和统一构建。远程操作单独记录真实结果。
