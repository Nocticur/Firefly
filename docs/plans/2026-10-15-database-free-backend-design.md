# 无数据库后台

用户要求彻底移除数据库，同时继续使用与博客一同部署的管理后台。使用现有 private Vercel Blob 保存受保护的 JSON 状态文件，GitHub 继续保存正式文章、站点配置与公开发布清单。保留草稿、历史、登录、审核、服务开关、发布、媒体、邮件与备份功能，不引入数据库替代产品。

每个站点及运行环境拥有独立文件路径和 Blob 凭据。文件包含带版本号的命名记录集合，所有读取绕过 CDN 缓存，写入使用 ETag 条件替换。首次创建禁止覆盖；竞争写入重新读取后执行同步、无外部副作用的更新函数。错误、文件损坏、版本不符或存储缺失均拒绝写入，不回退内存或临时磁盘。

会话只保存随机令牌摘要、CSRF 摘要和过期时间。登录限流持久保留单 IP 与站点总量，IP 仅保存 HMAC 摘要。同源、CSRF、Cookie 签名、密码派生、环境隔离及管理员校验保持生效。生产服务开关首次关闭。

正式发布先冻结内容和 Git 基线并保存任务，再调用 GitHub。未知外部结果进入核查状态，文件的原子更新和任务租约避免重复提交、重复发信。公开静态清单与原始文章在同一次 Git 提交更新，保留现有 URL、中文路径、MDX 与相对图片语义。

备份为私有 JSON 文件及媒体校验清单；恢复先校验、建立当前状态的保护备份，再原子替换允许恢复的内容。当前服务权限、外部发送事实及维护索引保留；会话清除，旧任务和未发送邮件阻止重放。恢复不再使用隔离 SQL 库或迁移脚本。

清理范围包含 PostgreSQL 依赖、连接代码、迁移目录、迁移命令、CI 数据库服务与环境变量。旧数据库专项测试改为文件存储及真实 HTTP 路由测试，并补充跨实例 CAS、竞争写入、损坏拒绝、环境隔离、限流、会话撤销、发布冲突和恢复验证。最终执行后台测试、两端类型检查、Astro 检查和统一 Vercel 构建。

状态文件限制为 16 MiB，适合单人博客的后台使用。媒体字节和备份文件独立存放，不塞入状态文件；超过限制拒绝本次保存并给出明确错误。此方案不承诺无限存储或免费额度，也不创建、购买或部署外部服务。
